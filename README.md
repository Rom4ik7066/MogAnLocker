# Моглокер — монитор защиты

Локальная Windows-утилита для обнаружения некоторых признаков окна-блокировщика. Это диагностический прототип, а не антивирус.

- `MogLocker.sln` и `MogLocker.csproj` — решение Visual Studio для Windows Forms на .NET Framework 4.8.
- `MogLocker.cs` — главное окно WinForms с общей тёмной графитовой темой, боковой навигацией по разделам «Главная», «AdBlock», «Мониторинг», «Defender», «Анлок» и «Настройки», монитор Windows и горячая клавиша.
- `SecurityTools.cs` — просмотр и выборочное удаление исключений Microsoft Defender через Windows PowerShell, безопасное снятие известных пользовательских ограничений Windows и проверка последнего GitHub Release.
- `AnimatedButton.cs` — общие скруглённые кнопки WinForms с плавным наведением и нажатием.
- `AdBlockModels.cs` — модели настроек, фильтр-листов, сетевых и косметических правил и статистики.
- `AdBlockStore.cs` — локальные настройки и кэш в `%LOCALAPPDATA%\MogLocker\AdBlock`; синхронизация записи между GUI и Native Messaging host.
- `FilterRuleEngine.cs` — разбор поддерживаемого подмножества ABP-синтаксиса и компиляция правил для браузерного DNR API.
- `FilterListService.cs` — HTTPS-загрузка списков, проверка размера и сохранение кэша; неудачное обновление не удаляет предыдущий кэш.
- `NativeMessagingHost.cs` — обработка фреймированного Native Messaging протокола, правила, статистика и журнал ошибок.
- `NativeMessagingRegistration.cs` — явная регистрация host для текущего пользователя в Chrome/Edge и путь к расширению.
- `AdBlockPanel.cs` — раздел AdBlock: переключатель, статистика, фильтр-листы, журнал, пользовательские правила, импорт/экспорт и Allowlist.
- `browser-extension/manifest.json` — разрешения и стабильный ID расширения Edge/Chrome MV3.
- `browser-extension/background.js` — установка сетевых правил через `declarativeNetRequest`, косметический CSS и передача фактических совпадений в локальный журнал.
- `popup.html`, `popup.css`, `popup.js` — небольшая панель расширения для переключателя, счётчика и исключения текущего сайта.
- `tests/AdBlockEngineSmokeTests.cs` и `tests/run-smoke-tests.cmd` — автономные проверки компилятора фильтров, Allowlist и локального хранения.
- `Launcher.cs`, `bootstrap.ps1`, `build.cmd`, `build-extension.ps1` — упаковка одного EXE, проверка .NET Framework, установка приложения и упаковка расширения.

## Мониторинг Defender и обновления

Раздел «Defender» — диагностический монитор, а не самостоятельный полноценный антивирус. В нём показаны состояния мониторинга Windows, исключений Defender и `regedit.exe`, а также доступны проверка исключений и переход к журналу. Для чтения настоящего списка исключений приложение запускает `Get-MpPreference` с повышением через стандартный запрос UAC; при отмене UAC отображается ясное сообщение, а ошибки доступа не показываются как элементы списка. Там можно отметить конкретные значения для удаления; перед изменением Windows снова показывает запрос UAC, а исключения удаляются командой `Remove-MpPreference`. После выполнения команда не перечитывает список автоматически: строки очищаются как неподтверждённые, и пользователь может отдельно обновить список (это снова запросит UAC). Никакие исключения автоматически не добавляются и настройки защиты не меняются без явного действия пользователя. Фоновая проверка через `Get-MpPreference` выполняется примерно раз в 30 секунд; если Windows не предоставляет данные без повышения, проверка сообщает о недоступности, а не подставляет фиктивные значения. Источник изменения определить нельзя: обнаружение изменения не доказывает, что оно было сделано именно PowerShell.

Раздел «Анлок» проверяет ограничения для Диспетчера задач, Редактора реестра, Командной строки и Панели управления. После подтверждения он удаляет только известные значения политик текущего пользователя из HKCU. Системные значения HKLM не изменяются; обнаруженная системная политика блокирует изменение, а организационные политики, записанные в HKCU, могут быть восстановлены при следующем обновлении политик Windows.

Монитор также сообщает о запущенном `regedit.exe` и продолжает отслеживать изменения наблюдаемых ключей реестра. Это диагностическое обнаружение, а не полноценный антивирус: приложение не блокирует процессы и не заменяет Microsoft Defender.

Проверка обновлений использует GitHub Releases репозитория `Rom4ik7066/MogAnLocker` по HTTPS с TLS 1.2. Новые версии приложения публикуются как Releases с тегом версии. Приложение предложит открыть страницу релиза; автоматического скачивания и установки нет.

## Запуск

### Обычный запуск

1. В Проводнике откройте папку проекта и перейдите в `bin`.
2. Запустите двойным щелчком `MogLocker.exe`.
3. При первом запуске загрузчик установит приложение для текущего пользователя и добавит ярлык «Моглокер» в меню «Пуск». Если не установлен .NET Framework 4.8, загрузчик сначала предложит скачать официальный установщик Microsoft.
4. При последующих запусках найдите «Моглокер» через меню «Пуск» и откройте его.

Используйте именно `bin\MogLocker.exe`: это готовый файл для запуска, содержащий загрузчик и приложение. Другие файлы проекта для обычного запуска не нужны. Если Windows предложит подтвердить установку .NET Framework, для этого может понадобиться подключение к интернету и подтверждение контроля учётных записей.

Приложение и загрузчик рассчитаны на Windows 10/11. Если .NET Framework 4.8 отсутствует, загрузчик покажет диалог согласия, скачает официальный web-установщик Microsoft, проверит его цифровую подпись и запустит стандартную установку. Загрузчик не обходит запросы прав Windows.

### Сборка из исходников

Для сборки требуется .NET Framework 4.8 Developer Pack или Visual Studio Build Tools. В Проводнике откройте папку проекта и запустите `build.cmd`. После успешной сборки запустите готовый файл `bin\MogLocker.exe`, как описано выше.

Чтобы открыть исходники, загрузите `MogLocker.sln` в Visual Studio 2019/2022 с установленным .NET Framework 4.8 Developer Pack. Сборка решения компилирует приложение; `build.cmd` дополнительно упаковывает launcher и расширение в готовый `bin\MogLocker.exe`.

### Подключение блокировки в Edge/Chrome

Сетевую фильтрацию выполняет отдельное расширение браузера: обычное WinForms-приложение не может легально блокировать HTTPS-запросы вкладок без браузерного API или установки системного корневого сертификата. MogLocker использует документированный Native Messaging API и MV3 `declarativeNetRequest`; перехват защищённых процессов, MITM-прокси и установка сертификатов не применяются.

1. Запустите MogLocker, откройте в боковом меню раздел «AdBlock» и нажмите «Подключить браузер». Подтвердите запись HKCU-моста для текущего пользователя.
2. Откройте `edge://extensions` или `chrome://extensions`, включите режим разработчика и нажмите «Загрузить распакованное расширение».
3. Выберите папку `browser-extension`, путь к которой показан в диалоге подключения. Для уже установленной сборки это `%LOCALAPPDATA%\Programs\MogLocker\<версия>\browser-extension`; при запуске непосредственно из Visual Studio — папка `browser-extension` рядом с собранным приложением.
4. Закрепите «MogLocker AdBlock» на панели браузера. Вкладка приложения и расширение используют общие правила и локальную статистику.

Расширение загружено как распакованное и использует разрешение `declarativeNetRequestFeedback`, чтобы показывать именно совпавшие с блокирующими правилами запросы. Поэтому реальная статистика совпадений и подключение Native Messaging проверяются в Edge/Chrome при установленном распакованном расширении с включённым режимом разработчика; публикация в магазине браузера потребует соответствующей проверки/переупаковки расширения.

AdBlock использует встроенный список распространённых рекламных доменов, EasyList и EasyPrivacy. Списки автоматически обновляются не чаще одного раза в сутки, пока MogLocker запущен; предыдущая локальная копия остаётся при сетевой ошибке. Правила кэшируются в `%LOCALAPPDATA%\MogLocker\AdBlock`. На встроенных лимитах браузерного DNR движок применяет до 3500 сетевых правил из загруженных списков, до 500 пользовательских правил и 2500 косметических правил. Неподдерживаемые директивы ABP пропускаются и подсчитываются в статусе вкладки; пользовательское неподдерживаемое правило отклоняется с объяснением. Поддерживаются сетевые шаблоны, исключения `@@`, типы ресурсов, `domain=`, first/third-party, косметические правила `##` и исключения косметических правил `#@#`; редиректы, popup-скрипты, процедурные CSS-фильтры и сложные директивы намеренно не эмулируются.

## Настройки приложения

В боковом меню откройте «Настройки», чтобы выбрать тёмную, светлую или системную тему, создать собственную тему с настройкой фона, поверхности, текста и акцентного цвета, а также выбрать стиль шапки Windows или macOS. В macOS-стиле цветные кнопки управляют окном; его границы можно перетаскивать для изменения размера. Здесь же можно включить/отключить анимации и заставку и указать папку для экспорта журнала. При сохранении журнала можно выбрать другой путь; выбранная папка запоминается. Настройки и пользовательские темы хранятся в `%LOCALAPPDATA%\MogLocker\settings.json`.

Кнопка «Настроить звук» объясняет и проверяет подключение саундпада к Discord Desktop. Для передачи звука в голосовой канал требуется отдельно установить виртуальный аудиодрайвер VB-CABLE: в саундпаде назначить `CABLE Input` вторым выходом, а в Discord Desktop выбрать `CABLE Output` как устройство ввода. MogLocker не устанавливает драйвер и не внедряет звук в Discord самостоятельно.

## Что отслеживается

- Полноэкранные окна известных браузеров без заголовка окна, занимающие не менее 90% одного дисплея. Обычные развёрнутые окна браузера с заголовком не считаются полноэкранными. Предупреждение добавляется один раз, пока окно остаётся в этом состоянии.
- Полноэкранные окна других программ, занимающие не менее 90% одного дисплея, если у окна отсутствует или отключена системная команда закрытия.
- При поиске таких окон системные процессы и процессы, запущенные из каталога Windows, исключаются. Неизвестные процессы, для которых не удалось определить исполняемый файл, также не предлагаются к завершению.
- Кнопка «Завершить выбранную» позволяет завершить процесс только для выбранного и повторно проверенного полноэкранного окна; перед действием требуется подтверждение. Для браузера дополнительно предупреждается о возможной потере вкладок и несохранённых данных. Системные процессы, процессы Windows и сам Моглокер защищены от завершения.
- Кнопка «Проверить Defender» запускает выборочную проверку файла выбранного стороннего приложения через Microsoft Defender после подтверждения пользователя. Возможен системный запрос прав администратора. Используется `-DisableRemediation`: сканер сообщает о находках, но не применяет к ним действия автоматически. Смотрите вывод окна Microsoft Defender и код результата в журнале Моглокера. Подробнее: [параметры MpCmdRun](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus).
- Кнопка «Помощь при блокировке» открывает памятку для выхода из мошеннической полноэкранной страницы браузера: Esc/F11, закрытие вкладки и, при необходимости, ручное завершение браузера через Диспетчер задач.
- `Ctrl+Alt+M` переключает Моглокер между свёрнутым состоянием и восстановленным поверх окон, если зарегистрировать сочетание не мешает другое приложение. Если Windows не смогла зарегистрировать сочетание, причина появится в журнале.
- Памятка описывает встроенные сочетания Windows: `Alt+Tab`, `Ctrl+Shift+Esc`, `Alt+F4` и `Ctrl+Alt+Delete`. Моглокер их не перехватывает; `Ctrl+Alt+Delete` является защищённым сочетанием Windows и не может быть подделан обычным приложением.
- Создание, изменение, переименование и удаление файлов в пользовательской и общей папках автозагрузки.
- Изменения выбранных параметров `Run`, `Winlogon` и политик, ограничивающих доступ к редактору реестра, диспетчеру задач и запуску программ.
- Состояние `explorer.exe` и доступность сетевого подключения.

Список наблюдаемых параметров реестра запоминается только в памяти при запуске программы. Поэтому программа сообщает об изменениях после запуска, но не устанавливает, что уже было изменено раньше.

## Ограничения и безопасность

- Программа анализирует метаданные окна и имя процесса, но не читает содержимое страниц, не распознаёт текст на снимке экрана (OCR) и не сохраняет снимки. Полноэкранные браузеры могут быть обычным режимом просмотра или презентации; проверяйте предупреждение вручную.
- Одновременно работает только один экземпляр Моглокера в сеансе Windows.
- Отсутствующая/заблокированная команда закрытия сама по себе не доказывает заражение: так устроены некоторые полноэкранные приложения и киоск-режимы.
- Изменения в папках автозагрузки и реестре могут быть штатными. Сверяйте событие с установленными вами программами.
- Утилита работает только в текущем сеансе и пока открыта. Она не завершает процессы автоматически и не удаляет/восстанавливает файлы или параметры реестра. Принудительное завершение выбранного процесса может потерять несохранённые данные.
- `Alt+F4` закрывает активное окно: перед нажатием убедитесь, что активно окно браузера, иначе можно закрыть Моглокер.
- Справка по браузерным блокировкам не пытается определять содержимое каждой вкладки и не закрывает браузер сама. Завершение браузера через Диспетчер задач выполняется пользователем и может привести к потере несохранённых данных.
- Журнал хранится в памяти процесса; кнопка копирования переносит его в буфер обмена только по запросу пользователя.

При подозрительном событии используйте Windows Security для полной или автономной проверки. Не удаляйте системные файлы и не меняйте реестр только на основании одного предупреждения.
